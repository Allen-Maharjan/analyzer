# News sources for gold, silver, and future NEPSE analysis

Research checked 3 November 2026. Plans and terms can change. This compares provider documentation, not a live-key evaluation; none of these providers' actual gold, silver, Nepal, or NEPSE coverage has been verified for this application.

## Recommended trial

Try **Marketaux** first, using a server-side API key and keyword/date queries. Its free plan advertises current news and offers enough daily requests to support a search when a new Nepal price is recorded. Three results per request make relevance and source diversity a significant constraint. Before adopting it, run a short live-key trial with separate gold, silver, Nepal, and NEPSE queries; check result relevance, timestamps, source diversity, permitted storage and display, and account-specific terms. Do not infer Nepal coverage from the provider's global-market count.

Provider-stated freshness is not a guarantee of coverage, article publication latency, or service availability. Broad media search can be supplemented with public primary sources such as [Federal Reserve news releases and RSS feeds](https://www.federalreserve.gov/feeds/feeds.htm), which can substantiate monetary-policy events but cannot replace general news discovery.

## OpenRouter search

A free OpenRouter reasoning model does **not** make web search free. The current [OpenRouter web search server tool](https://openrouter.ai/tool/web-search/) lists, for example, Exa instant/fast/auto at $0.007 per search request, Parallel turbo/fast at $0.001, and Parallel basic/advanced or Perplexity at $0.005, with additional result charges on some engines and native provider pricing where applicable. The model may run zero or multiple searches in one response, so costs can vary. Check current pricing and any account requirements before enabling it. OpenRouter also offers a [web search plugin](https://openrouter.ai/docs/guides/features/plugins/web-search), whose pricing and behavior differ from the server tool; do not conflate the two.

The application's existing OpenRouter free-model selection does not itself perform web search. A news-provider search and an optional model summary are separate operations. Search results should remain independently stored and inspectable; free-model reasoning should not be treated as an independent source of facts.

## Integration considerations

- Detect a newly inserted or meaningfully revised Nepal price for each metal and enqueue a durable news-refresh job. Repeated page loads and unchanged refreshes should use saved results, not trigger searches. Record the trigger transactionally with the price change when possible.
- Search with asset-specific terms and a bounded time window. Save article URL, source, headline, publication timestamp where available, retrieval timestamp, and allowed metadata; deduplicate by canonical URL and preserve source attribution. Verify provider terms before retaining content or displaying snippets.
- Record success, empty results, delay, stale data, quota exhaustion and failures separately. Retry transient failures with bounded backoff; don't interpret a failed or delayed request as proof that there is no news.
- Marketaux and EODHD examples put the API key in a query parameter. Keep keys on the server, and redact query strings from HTTP-client logs, exceptions and telemetry; the existing shared HTTP helper must be reviewed before reuse. Never expose keys in the browser or article URLs.
- Treat external text and model output as untrusted. Present sourced evidence and make any influence on BUY/WAIT a bounded, deterministic rule based on validated facts; a model-generated headline summary alone should not create evidence or change the authoritative decision. News direction and predictive value need backtesting separately for each asset.
- Validate NEPSE company identifiers and Nepal-specific news coverage in a live trial before promising support. No provider trial or account signup was performed for this research.
